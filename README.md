# Junior Dev Scaffolding & Client Requirement Exam Simulator

> An exam conditioning single-page web application designed to train junior web developers in client brief analysis, semantic HTML5 scaffolding, CSS layout mechanics, requirement sufficiency assessment ("Is it enough? Why / Why not?"), and zero-hallucination engineering principles.

---

## 🎯 Core Mission

In technical exams and junior developer interviews, candidates frequently lose points by:
1. **Inventing unstated features** (shopping carts, login modals, database schemas) when the client never requested them.
2. **Accepting subjective adjectives** ("warm, modern, clean vibes") as actionable CSS specifications without requesting approved brand assets.
3. **Using non-semantic div soups** instead of accessible W3C landmarks and relative typography units.

This simulator conditions developers to audit messy client briefs, establish requirement boundaries, and scaffold standard-compliant architectures before writing premature code.

---

## 🚀 Features & Modules

### 1. The Non-Negotiable Junior Dev Mindset
- **"Zero Hallucination" Rule:** Hard boundaries against assuming or fabricating unstated requirements.
- **The "Enough vs. Not Enough" Test:** Distinguishing between client feelings and engineering constraints.
- **Semantics Over Appearance:** Enforcing W3C landmarks (`<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`, `<footer>`).

### 2. The "Is It Enough?" Audit Matrix
Interactive dimension auditing for:
- Content Hierarchy & Information Priority
- Target Viewports & Responsive Adaptation
- Form & Interaction Specs
- Media, Visual Assets & Performance Budgets
- *Junior Dev Script:* Copyable professional response template for explaining requirement insufficiency to clients.

### 3. Standards & Architecture Cheatsheet
- **Tab A:** Semantic Scaffolding & Accessible Forms (`<label for="...">`)
- **Tab B:** CSS Layout Geometry (1D Flexbox vs. 2D CSS Grid)
- **Tab C:** Box Model & Sizing (`box-sizing: border-box`, padding vs margin) with interactive diagram
- **Tab D:** Mobile-First Responsive Foundations (`rem`, `vw`, fluid scales)

### 4. The 4-Step Technical Essay Blueprint
Universal framework for structured exam answers and client proposals:
1. **Step 1:** Direct Verdict (`SUFFICIENT` / `INSUFFICIENT` / `CSS GRID` / `REJECT`)
2. **Step 2:** Scenario Clues & Evidence
3. **Step 3:** Standards & Architectural Rationale (W3C HTML5, WCAG 2.1 AA/AAA)
4. **Step 4:** Risk / Failure Analysis

### 5. Interactive Mock Exam Conditioning Drills (Q1 to Q5)
- **Drill 01: Artisan Coffee & Pastry Shop ("Kape Kultura")**
  - Scope boundaries, 18-item catalog grid architecture, mobile contact prioritization.
- **Drill 02: Barangay Health Clinic Portal ("Barangay 4")**
  - Low-end smartphone optimization, senior accessibility (WCAG AAA), tabular doctor schedule architecture, and file download fallbacks.
- **Interactive Tools:**
  - 🛡️ **Exam Mode:** Locks model answers until you draft your own response.
  - 💡 **Key Clue Highlighter:** Visualizes constraints inside scenario briefs.
  - 💾 **Local Storage Persistence:** Real-time autosave of drafted answers and rubric checklists.
  - 📊 **Self-Grading Rubrics:** Checkboxes to calculate readiness score percentages.
  - 📝 **Markdown Report Export:** One-click download of all drafts and benchmarks.

## 🛠️ Tech Stack

- **HTML5:** Semantic W3C markup with accessible ARIA landmarks.
- **CSS3:** Modern Developer IDE Dark Theme (`#0b0f19`, `#151e32`, `#223250`, `#38bdf8`), CSS custom properties, responsive grid/flexbox, custom animations, print stylesheet.
- **JavaScript (ES6):** Vanilla JavaScript (no frameworks or dependencies required).
